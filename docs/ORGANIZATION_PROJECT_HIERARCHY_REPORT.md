# 運営団体・プロジェクト階層 実装報告

## 目的

ワタシワークス全体をシステム管理に限定し、利用者向けのすべてのプロジェクトを運営団体の配下へ置く。

## 実装後の構造

```text
ワタシワークス全体
├── 運営団体A
│   ├── 千ノ国メディア
│   └── 副業
└── 運営団体ワタシワークス
    └── 企業向け
```

実データでは、運営団体を`Workspace(type=ORGANIZATION)`、プロジェクトを`Group`、公開設定を`ServiceConfiguration`で表現する。Groupは必須の`workspaceId`を持ち、公開設定は`workspaceId + groupId`の複合参照で親子関係を固定している。既存の作成処理もACTIVEなORGANIZATIONだけを親として受け付ける。

## 画面の変更

- システム管理メニューを「ワタシワークス全体 / システム管理」と表示する。
- 「グループ管理」を「プロジェクト管理」へ変更する。
- 公開名・URL・ブランド設定を「サービス管理」ではなく「公開設定」として表示する。
- システム管理者の一覧を、運営団体ごとのプロジェクト一覧として表示する。
- 団体運営者の画面でも、団体の中にプロジェクトを作る順番を明示する。
- プロジェクト運営者に、親団体と管理対象プロジェクトを表示する。団体全体の管理ボタンは団体所有者・団体運営者だけに表示する。

## 権限

`PlatformAdmin`はシステム全体の設定、`WorkspaceMembership`は運営団体、`GroupMembership`はプロジェクトを管理する。プロジェクト運営者へ親団体を表示しても、団体情報や他プロジェクトを操作する権限は付与しない。
